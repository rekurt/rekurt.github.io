# Individual product websites

The user authorized autonomous delivery of individual persuasive sites. The existing family kit provides deployment, metadata and reciprocal navigation, but its identical metadata-first hero does not satisfy this objective.

## Delivery requirements

- Give every curated product a distinct value proposition, audience, visual presentation, demonstration and primary adoption action.
- Keep Mac Coffee, VPN Hub and chislo's existing individual landing experiences, which already contain benefits, product demonstrations and adoption actions. Review their published integration as part of final verification.
- Replace the generic generated landing for git-barber, ymsdk, gost-crypto, dbdiff, depth, gitlab-downloader, go-propisyu and prt.
- Present CortexForge as an experimental lab and sprint-velocity as a small automation recipe. Do not imply enterprise maturity, invented adoption, certification, performance or security guarantees.
- Preserve openkline.tech's existing individual marketing site and integrate its author/project-family navigation. Its separate playground and API documentation remain available at GitHub Pages.
- Publish full English, Russian and Simplified Chinese marketing content. Code, API names and Russian-language library output remain in their original language.
- Preserve family navigation, catalog discovery, automatic metadata updates, canonical URLs, sitemaps and installation/documentation paths.

## Implementation

Embed reviewed product profiles alongside the Go site kit. Each profile carries independently authored localized copy, a visual theme, a product-specific demonstration and an adoption path. Shared infrastructure owns semantics, navigation, localization and accessible controls; profiles own the story. Themes change composition, typography, spacing and product visuals as well as color.

Use actual repository images where available (git-barber, depth, prt), pinned to the catalog source revision. Other demonstrations are clearly labelled illustrative API/workflow examples. Keep repository documentation available below the landing in a disclosure so the marketing narrative remains readable.

## Verification

Validate all locale profiles and rendered sites, including primary CTA destinations, safe assets, localized headings and distinct demonstrations. Build and validate every generated product against its real checkout. Confirm successful deployment and inspect production output for the profile identity, headline, canonical metadata and family navigation. A green legacy fleet check alone does not prove the new marketing requirements.
